# Security Policy

## Report a security or privacy issue

Do not publish API keys, tokens, personal contact details, participant records, payment information, confidential contracts, raw complaint data, or directly exploitable steps in an Issue, Discussion, or Pull Request.

Prefer GitHub's private vulnerability reporting feature on the repository's **Security** page. If that feature is unavailable, open an Issue without sensitive or technical details and request a private communication channel.

Useful reports include:

- Instructions or templates that may expose credentials, personal information, or local paths.
- Generated output that could be mistaken for verified actual results.
- Spreadsheet content that could trigger formula execution.
- Process gaps that could bypass required human approval for outreach, spending, contracts, refunds, publication, participant-data processing, or on-site safety decisions.

## Response principles

- Protect affected people, data, and credentials before publishing details.
- Revoke or rotate an exposed real credential; deleting a file is not sufficient.
- Keep reports minimal and redact sensitive values.

## Scope

This policy covers the Skill, deterministic generator, example brief, validation workflow, and repository documentation. It does not provide a security, legal, privacy, or compliance warranty.

## 中文说明

### 报告安全或隐私问题

请不要在 Issue、Discussion 或 Pull Request 中发布 API Key、Token、个人联系方式、参与者名单、支付信息、保密合同、原始客诉数据或可直接利用的攻击步骤。

优先使用仓库 **Security** 页面中的私密漏洞报告功能。若该功能不可用，请只创建不含敏感信息和技术细节的 Issue，请求维护者提供私密沟通方式。

建议报告：

- 可能暴露凭证、个人信息或本机路径的指令与模板。
- 容易把模拟数据误认为真实结果的生成内容。
- 可能触发表格公式执行的输出内容。
- 可能绕过外联、支出、合同、退款、发布、参与者数据处理或现场安全人工审批的流程缺口。

### 处理原则与范围

- 先保护受影响的人、数据和凭证，再处理公开说明。
- 若真实凭证已经暴露，应立即撤销或轮换；删除文件本身并不足够。
- 报告只保留最少必要信息，并对敏感值做脱敏。
- 本政策覆盖 Skill、确定性生成器、示例 Brief、校验工作流和仓库文档，不构成安全、法律、隐私或合规保证。
